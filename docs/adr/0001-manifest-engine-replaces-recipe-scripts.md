# Declarative manifest + engine replaces per-domain recipe scripts

The repo previously had six `recipes/*/run.sh` scripts, each a linear bash blast through a domain (core deps, bluetooth, window manager, user apps, dev env, backups), with no per-tool detection and manual invocation in a manually-remembered order. We considered a thin orchestrator that just sequences the existing scripts, but that only gets recipe-level granularity — it can't answer "is fzf installed" or offer per-tool interactive selection, which was the actual goal. We instead replaced the run.sh scripts with a Manifest of Entries and a single generic engine (`chest`) that checks and installs each Entry individually. This is the harder rewrite but is what makes per-tool detection, category-grouped interactive picking, and cross-machine drift-checking possible at all.

# bin/ holds thin launcher shims; real implementations live in packages/

Originally `bin/` held full script implementations directly (matching `ide`/`llmt`/`vspeed` as they exist today). This stopped fitting once `chest` needed its own multi-file Engine plus the Manifest and Config entries' source files — those don't belong flattened into `bin/` alongside genuinely independent one-file scripts (see the Independent tool vs. chest distinction in CONTEXT.md). Resolution: `bin/` now holds only thin shims (a few lines each) that resolve into `packages/<name>/main.ts`, via `ENVIRONMENT_REPOSITORY` once copied into `$GLOBAL_BINS`. This keeps `bin/`'s meaning literal — "things that end up in your PATH" — while each tool's actual code, however large it grows, lives in its own `packages/<name>/` directory. Applies uniformly to `chest` and the Independent tools alike, even though only `chest` currently needs the extra room.

# Bun + TypeScript engine, run interpreted, with a bash bootstrap for the pre-Bun gap

The engine needs richer interactive prompts (typed multiselect, per-item spinners, colored status) than bash TUI tools like `gum`/`fzf` give cleanly, and Bun/TypeScript is the ecosystem already used daily. The obvious objection is bootstrap: a brand-new Mac has no Bun. We resolved this by keeping the engine always run interpreted (`bun run cli.ts`, no compile/rebuild step ever, since the CLI always needs this repo checked out anyway) and isolating the one pre-Bun gap into a standalone `bootstrap.sh` (plain bash — installs Homebrew, then Bun) that is the sole thing outside the Manifest/engine model. We considered a Bun-compiled standalone binary to remove even that gap, but rejected it since it would reintroduce a rebuild step on every Manifest edit for no benefit, given the CLI is never meant to run without the repo present.

# chest takes no arguments — one Sweep covers every use case

We initially designed `chest` with a category argument (`chest config`, `chest cli`, ...) plus a separate `chest bin`, reasoning that a quick "did I sync gitconfig" check shouldn't have to walk the whole Manifest. This was reversed: all four actual use cases (new-machine setup, checking what's installed, resyncing a just-edited config/bin file, checking config/bin are in sync) turn out to be the same action — run a Sweep and look at what's flagged — just performed at different times, not different operations. Category remains an on-screen grouping label (see CONTEXT.md), but has no corresponding CLI argument. Checks are cheap enough (sub-second each) that always sweeping everything costs nothing meaningful, and a single zero-argument command is simpler to remember than deciding which scoped variant applies.

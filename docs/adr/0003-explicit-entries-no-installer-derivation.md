# Every Entry is fully explicit; no auto-derived checks by installer type

We considered giving Entries a typed `installer` field (`brew`, `cask`, `pnpm`, ...) so the engine could auto-derive `check` and `install` for common cases, cutting most of the ~40 Entries to one line. This was rejected deliberately in favor of every Entry always writing its own `check` and `install` explicitly, duplication across near-identical brew Entries accepted. The reasons: auto-derivation is itself a source of bugs (e.g. casks install `.app` bundles, not binaries — a naive `command -v` check silently breaks for them), and system-action Entries that aren't package installs at all (dock settings, `ssh-keygen`, `chsh`) don't fit a typed-installer model cleanly anyway, so a uniform explicit shape covers every Entry with one mental model instead of two. A future maintainer should not "fix" the duplication by reintroducing per-kind derivation — it was tried and rejected on purpose.
